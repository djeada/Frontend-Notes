# Additional resources: use a curated reference list well

[Original resource directory](../13_additional_resources.md) · [All chapter updates](README.md)

The original directory is a useful collection of inspiration and tooling, but links are not endorsements, and availability, free tiers, licenses, and pricing change. Select resources by task, check their current documentation, and prefer primary sources for technical definitions.

## What to check before reuse

1. **License and attribution:** an asset being downloadable does not imply it is freely reusable in commercial products. Check redistribution, modification, attribution, and model-release requirements for icons, photos, fonts, logos, and templates.
2. **Accessibility:** preview typefaces at body sizes, check glyph coverage, test text contrast, and verify keyboard behavior of borrowed components. A pleasing screenshot cannot validate usable code.
3. **Maintenance and compatibility:** verify recent releases, browser support, dependencies, security guidance, and framework-version compatibility before installing a component library.
4. **Performance and privacy:** optimize downloaded images, avoid unnecessary third-party embeds, and consider whether a service collects data from visitors or sends requests to external hosts.
5. **Provenance:** verify whether a generated or community-shared template includes copied assets that require separate permission.

## A task-oriented starting set

| Need | Primary place to start | Reason |
| --- | --- | --- |
| HTML, CSS, JavaScript behavior | [MDN Web Docs](https://developer.mozilla.org/) | Explanations, compatibility notes, and references |
| HTML language rules | [WHATWG HTML Standard](https://html.spec.whatwg.org/multipage/) | Normative HTML behavior |
| CSS module status | [W3C CSS Snapshot](https://www.w3.org/TR/css-2026/) | Explains independent CSS modules |
| Accessibility requirements | [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) | Testable accessibility success criteria |
| Application security | [OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/) | Practical threat-specific guidance |
| Browser compatibility | [MDN compatibility data](https://github.com/mdn/browser-compat-data) | Feature support data, with version context |
| Frontend performance | [web.dev performance](https://web.dev/learn/performance) | Measurement and improvement techniques |

The original chapter remains an inspiration catalog for templates, icons, stock photos, generators, and mockups. Recheck each catalog link before recommending it as a current tool. The presence of an official-looking name does not establish that a UI component is maintained or that an image has a permissive license.

## Practice

Choose one photo, one font, and one UI component from the original directory. Record their publisher, license URL, attribution requirements, download date, and last-released version (when relevant). Test the component with a keyboard and 200% zoom, then note any issues before using it in a project.

**References:** [Creative Commons: licenses](https://creativecommons.org/share-your-work/cclicenses/), [W3C: accessibility evaluation](https://www.w3.org/WAI/test-evaluate/), [web.dev: image performance](https://web.dev/learn/images).
